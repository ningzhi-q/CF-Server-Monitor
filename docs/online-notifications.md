# 上线提醒

管理端「设置 → 通知」新增「上线提醒」下拉开关，位于离线告警旁边，可选择禁用或启用。节点离线后恢复上线时，通过已配置的内置通知渠道、SMTP 或自定义 Webhook 通知一次。

## 开关与兼容

| 离线告警 | 上线提醒 | 行为 |
| --- | --- | --- |
| 禁用 | 禁用 | 不查询节点状态，也不发送离线或上线通知 |
| 启用 | 禁用 | 按离线阈值发送离线告警，恢复时静默清除状态 |
| 禁用 | 启用 | 超过 5 分钟未上报后静默记录离线，恢复时发送一次上线提醒 |
| 启用 | 启用 | 使用离线告警的分钟阈值，分别发送离线和恢复通知 |

已有站点没有 `online_notify` 字段时，仍随离线告警启用恢复通知。保存后开关作为独立值保留，修改离线告警不会覆盖显式选择。新站点默认关闭两类通知。

首次检测时，当前已经在线的节点不会集中发送提醒。没有上报记录的节点先记录为离线，之后收到有效上报时可触发一次上线提醒。已设置 `offline_notify_disabled = '1'` 的节点沿用旧版行为，不参与离线或上线检测。

通知由每分钟任务检查，恢复上报后在下一次有效检查发送；每周日 UTC 00:00–00:04 表轮换窗口暂停检测。通知使用原有「节点恢复通知」事件文案、✅ 图标、节点名称、通知语言、时区和模板。

## 配置与实现

- `online_notify` 存储在 `settings.site_options`，对外为 `'true'` 或 `'false'`，无需新增数据库列。
- 加载、保存、导入时统一规范布尔值。旧配置缺失、`null` 或空字符串时，以 `tg_notify` 是否开启兼容旧行为。
- `save_settings` 合并现有配置后检查通知渠道，因此单独启用上线提醒或删除仍在使用的通知地址也会校验。
- `checkOfflineNodes` 同时处理离线与上线状态，共用批量时间戳查询和持久化的 `alert_state`。仅在状态变化时写入；写入成功后发送，持续上报不重复提醒。
- 时间戳读取、状态读取或状态写入失败时跳过通知，保留之前的状态等待下一次检查。
- 设置缓存、备份导入导出和七种管理端语言都包含新开关；无需修改公共主题接口或 Agent 上报协议。
